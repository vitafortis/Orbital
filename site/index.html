Claude Code sessions on your own hardware

Pick a repo and Claude Code starts in its own container on your servers, with a terminal in the browser, live summaries of every session, and sessions you can stop and pick up again.

Install with Docker Read the docs

One container per session, one place to watch them all

Orbital clones the repo into a fresh container, starts the agent inside tmux, and keeps the clone, home folder and conversations in a volume. Containers are disposable; nothing is rebuilt per project.

A real terminal, in any browser

Open a session as a full terminal. Closing the tab doesn't stop it, and several people can watch the same one.

  • Questions as buttons: permission prompts and choices show above the terminal.
  • A Shell tab opens a second terminal in the same container.
  • Attach files by pasting or dropping them: screenshots, logs, anything.
  • Remote Control: subscription sessions also show up in claude.ai and the Claude app.

Readable on a phone

The Read tab formats the conversation from Claude Code's transcript: the latest turn in full, earlier ones folded, what's new since you last looked, and a box to reply.

What a session needs from you, such as a login, a command to run or an approval, lands in one To do list with the exact command to copy.

Skills, pull requests and automations

Start a session from a skill instead of a message, such as /code-review on a pull request. Skills live in a shared Library, written in Orbital or taken from a folder in any repo.

Label a Linear issue and a session starts on its own, on Linear's branch name, and comments back with the pull request.

Ready for a team

  • Single sign-on with any OpenID Connect provider or your reverse proxy, and SSO-only sign-in.
  • Roles: admins, members and viewers, enforced on the server. Raise someone for a few hours, or let them ask.
  • Yours and the organization's: people sign in to their own Claude plan and GitHub; API keys, cloud accounts and GitHub Apps stay with admins.
  • Shared sessions anyone can run, and private ones others see by name only.
  • Expiry: stop idle sessions and delete old ones on a schedule.

How Orbital keeps credentials apart →

Credentials stay on the server

Tokens and keys are encrypted at rest and never sent back to the browser. A session gets only what it's given, as files in its own container.

GitHub Apps

For organizations that allow apps but not personal tokens. Orbital keeps the hour-long installation tokens renewed, also inside running sessions.

AWS through SSO

Sign in to IAM Identity Center once. Each session gets only its profiles' short-lived keys, renewed while it runs.

Your Notion

Each person connects their own Notion, and Claude in their sessions reaches it as them, through Notion's hosted MCP server.

Up in a minute

All you need is Docker. Everything else is set up in the browser: create the admin, sign in to a model account, add GitHub, start a session.

Installation guide 
mkdir orbital && cd orbital
curl -fsSLO https://raw.githubusercontent.com/vitafortis/Orbital/main/compose.yaml
docker compose up -d
# then open http://<your-host>:3050
